HTML — Complete Documented Notes

From Absolute Zero to Interview-Ready

Part 1 — What Actually Happens When You Open A Website

Core definitions

  • Website — a collection of linked pages under one domain (e.g. amazon.com).
  • Web page — a single document within that website.
  • Browser — software (Chrome, Firefox, Edge, Safari) that requests pages and renders them visually.
  • Server — a remote computer that stores website files and sends them out when requested.

Step-by-step: typing a URL and hitting Enter

  1. You type https://example.com and press Enter.
  2. Browser performs a DNS lookup — converts the domain into an IP address.
  3. Browser opens a connection and sends an HTTP(S) request.
  4. Server sends back an HTTP response containing the HTML file.
  5. Browser parses the HTML top to bottom.
  6. Browser builds the DOM (Document Object Model) — a tree structure in memory.
  7. Linked CSS is parsed into the CSSOM; DOM + CSSOM combine into a render tree.
  8. Browser calculates layout, then paints pixels to the screen.
  9. Linked JavaScript runs, which can further modify the DOM live.

What each layer does

LayerResponsibilityAnalogy
HTMLStructure & contentSkeleton of a house — walls, rooms
CSSAppearance & layoutPaint, furniture, interior design
JavaScriptBehavior & interactivityElectricity — switches, automation
HTML exists because browsers need a universal, standardized way to describe "this is a heading, this is a link" so any browser on any device renders the same content correctly.

Part 2 — The Basic HTML Document

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, World!</h1>
</body>
</html>
LineWhy it exists
<!DOCTYPE html>Forces modern "standards mode" rendering instead of legacy "quirks mode." Must be the very first line.
<html lang="en">Root element; lang helps screen readers and search engines.
<head>Metadata container — not directly visible.
meta charset="UTF-8"Character encoding; supports virtually every language/symbol.
meta viewportMatches page width to device width for correct mobile rendering.
<title>Tab text, bookmark text, search-result headline.
<body>Everything the user actually sees.
Hands-on: save this as index.html, change the title, add a <p> below the heading, open the file directly in a browser.

Part 3 — HTML Syntax

  • Tag — the markup keyword: <p> (opening), </p> (closing).
  • Element — opening tag + content + closing tag: <p>Hello</p>.
  • Attribute — configuration inside the opening tag: href="page.html".
  • Nesting — elements inside elements create parent → child → sibling relationships.
  • Void/empty elements — no closing tag: <img>, <br>, <hr>, <input>, <meta>.
Bad: <p>Hello (unclosed tag — browser guesses where content ends, causing broken layout)
Good: <p>Hello</p>

Part 5 — Headings & Document Structure

Headings create a logical outline. Screen readers jump heading-to-heading; search engines weigh heading structure heavily.

Exactly one <h1> per page. Never skip levels just to get smaller text — that's CSS's job.

Part 6 — Links

<a href="about.html">About</a>                                  <!-- relative -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">External</a>
<a href="mailto:someone@example.com">Email us</a>
<a href="tel:+911234567890">Call us</a>
<a href="#section2">Jump to Section 2</a>                        <!-- fragment -->
  • Absolute URL — full address, works from anywhere: https://example.com/about.
  • Relative URL — path relative to current file: about.html, ../images/logo.png.
  • Fragment link — #id scrolls to the element with that matching id.
Security: without rel="noopener", a tab opened via target="_blank" can access window.opener and redirect your original tab — a phishing risk called "tabnabbing." Always pair the two.

Part 7 — Images

<figure>
  <img src="chart.png" alt="Sales grew 20% in Q3" width="600" height="400" loading="lazy">
  <figcaption>Q3 sales performance</figcaption>
</figure>
  • src — image path.
  • alt — screen-reader description, fallback text, image-search indexing. Use alt="" for decorative images.
  • width/height — reserve space before the image loads, preventing layout shift.
  • loading="lazy" — defers off-screen images until needed.
  • <figure>/<figcaption> — groups an image with its caption.

Part 8 — Lists

<ul>
  <li>Milk</li>
  <li>Bread</li>
</ul>

<ol>
  <li>Preheat oven</li>
  <li>Mix ingredients</li>
</ol>

<dl>
  <dt>HTML</dt>
  <dd>Markup language for structuring web pages</dd>
</dl>
  • <ul> — unordered, order doesn't matter.
  • <ol> — ordered, sequence matters.
  • <dl>/<dt>/<dd> — term/definition pairs, e.g. glossaries and FAQs.

Lists nest for submenus. Navigation menus are almost always <ul><li><a>.

Part 9 — Tables

<table>
  <caption>Student Marks</caption>
  <thead>
    <tr><th>Name</th><th>Subject</th><th>Marks</th></tr>
  </thead>
  <tbody>
    <tr><td>Rahul</td><td colspan="2">CS & Maths — 180</td></tr>
  </tbody>
</table>
  • <thead>/<tbody>/<tfoot> — group header, body, footer rows.
  • colspan/rowspan — merge cells across columns/rows.
  • <caption> — describes the table for accessibility.
Rule: use tables only for genuinely tabular data. Never for page layout — screen readers try to read layout tables as data grids, and they don't respond well to responsive design. Use CSS Grid/Flexbox for layout.

Part 11 — Semantic HTML

Semantic means the tag name describes its purpose. <nav> tells browsers, screen readers, and search engines "this is navigation." A <div class="nav"> tells the browser nothing.

<header>
  <h1>Site Name</h1>
  <nav>
    <ul><li><a href="#home">Home</a></li></ul>
  </nav>
</header>
<main>
  <section>
    <h2>Latest Posts</h2>
    <article>
      <h3>Post Title</h3>
      <p>Post content...</p>
    </article>
  </section>
  <aside><h2>Related Links</h2></aside>
</main>
<footer><p>&copy; 2026 My Site</p></footer>
TagMeaning
headerIntro content for a page or section
navPrimary navigation links
mainDominant unique content, one per page
sectionThematic grouping, usually with a heading
articleSelf-contained content that could stand alone
asideTangential content — sidebar, related links
footerClosing content — copyright, links
details/summaryNative collapsible disclosure widget
addressContact info for the page/article author
Decision guide: if content could stand alone/be syndicated → <article>. If it's a themed part of the current page → <section>. If neither and you just need a wrapper → <div>.

Part 12 — Div and Span

<div> = generic block container. <span> = generic inline container. Neither carries meaning — use only when no semantic tag fits.

Bad (div soup): 
<div class="header"><div class="nav"><div class="nav-item">Home</div></div></div>
Good (semantic): 
<header><nav><a href="#home">Home</a></nav></header>

Part 18 — The <head> Section

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page Title</title>
  <meta name="description" content="Summary for search engines">
  <meta name="robots" content="index, follow">
  <link rel="canonical" href="https://example.com/page">
  <link rel="icon" href="/favicon.ico">
  <link rel="stylesheet" href="/css/style.css">
  <script src="/js/app.js" defer></script>
</head>

Essential: charset, viewport, title. Optional (SEO/perf): description, canonical, favicon, preload.

Part 19 — HTML + CSS

<p class="intro">Welcome</p>
<a href="/x" id="cta">Get Started</a>

/* CSS */
p { color: gray; }                 /* element selector */
.intro { font-weight: bold; }      /* class selector */
#cta { background: orange; }       /* id selector */
a[target="_blank"] { color: red; } /* attribute selector */

Semantic HTML gives CSS meaningful, stable selectors (nav a) instead of fragile class chains (.header-nav-wrapper .nav-link-item).

Part 20 — HTML + JavaScript

<script>console.log("Inline — small snippets only");</script>
<script src="app.js" defer></script>
  • defer — runs in order, after parsing completes. Sensible default.
  • async — runs as soon as downloaded, order not guaranteed. Good for independent scripts (analytics).
<h1 id="title">Old text</h1>
<script>
  document.getElementById("title").textContent = "Changed by JS!";
</script>

Flow: HTML → DOM built → JS reads/modifies DOM → browser repaints instantly, no reload.

Part 21 — The DOM

The DOM is the browser's live, in-memory tree of the parsed HTML — not the file itself. JavaScript reads and writes to it, and the browser repaints on change.

HTML:
<body>
  <h1>Hello</h1>
  <p>Welcome</p>
</body>

DOM Tree:
document
└── html
    └── body
        ├── h1
        └── p
document.querySelector("h1");
document.getElementById("title");
document.querySelectorAll("p");

Part 22 — Accessibility

  • Semantic HTML first — a native <button> is keyboard-focusable and correctly announced by default; a styled <div> is not.
  • Always: alt on images, label on inputs, logical heading order, full keyboard reachability.
  • <button> for actions, <a> for navigation — never swap them.
ARIA rule: "No ARIA is better than bad ARIA." Use aria-* only when no native semantic tag already conveys that meaning.

Part 23 — SEO Basics

  • <title> — biggest on-page SEO signal.
  • meta description — the search-result snippet.
  • Heading hierarchy and semantic tags help crawlers understand structure.
  • alt text → image search indexing.
  • rel="canonical" — official URL for duplicate content.
  • meta robots — index/noindex, follow/nofollow control.
HTML controls structure/crawlability only — rankings also depend on content quality, speed, and backlinks.

Part 24 — Security Basics

  • Never hardcode passwords/API keys in HTML/JS — visible via "View Page Source."
  • XSS: unescaped user input rendered into the page lets attackers inject scripts — always escape user-generated content.
  • Always use HTTPS, especially with login forms.
  • iframe sandbox restricts embedded third-party content.
  • Client-side validation is UX only — server must always re-validate.

Part 27 — Browser DevTools

  • Elements — inspect/live-edit the DOM and CSS.
  • Console — run JS, view errors/logs.
  • Network — every request the page loads and its timing.
  • Sources — debug JS with breakpoints.
  • Responsive mode — preview at mobile/tablet sizes.
Edits made in DevTools are temporary — they vanish on refresh. Real fixes must go back into your source files.

Part 28 — Common Mistakes

1. Unclosed tag: <p>Hello<p>
Fix: <p>Hello</p>
2. Wrong nesting order: <b><i>Text</b></i>
Fix: <b><i>Text</i></b>
3. Duplicate IDs: two elements with id="box"
Fix: unique ids per element
4. div instead of semantic tag: <div class="title">My Page</div>
Fix: <h1>My Page</h1>
5. br for spacing: Line1<br><br><br>Line2
Fix: use CSS margin
6. Table for layout: arranging sidebar/content in a <table>
Fix: CSS Flexbox/Grid
7. Missing alt: <img src="dog.jpg">
Fix: <img src="dog.jpg" alt="A dog running">
8. No label: input with only a placeholder
Fix: pair with a proper <label for>
9. Skipped heading levels: h1 → h4
Fix: keep sequential order
10. Missing viewport tag — page unreadable on mobile
Fix: always include meta viewport
11. div as button: <div onclick="...">
Fix: use a real <button>
12. Link used for an action: <a href="#" onclick="deleteItem()">
Fix: <button onclick="deleteItem()"> — links are for navigation only

Part 29 — Best Practices

  • Prefer semantic HTML over generic div/span.
  • Consistent indentation (2 or 4 spaces).
  • Meaningful class names (product-card, not d1).
  • Build accessibility in from the start.
  • Write valid HTML — validate occasionally.
  • Keep HTML/CSS/JS in separate files.
  • Avoid unnecessary wrapper divs.
  • One h1, logical heading order, descriptive links (SEO).
  • Progressive enhancement: works with plain HTML first, then CSS/JS layer on top.

Part 30 — Interview Q&A

1. What is HTML?
A markup language defining page structure/content. Not a programming language — no logic, loops, or conditionals.
2. HTML vs HTML5?
HTML5 added semantic tags, native audio/video, new input types, canvas/SVG, offline storage.
3. Semantic HTML?
Tags whose names describe meaning (article, nav) vs generic containers.
4. div vs span?
div = block-level; span = inline. Both meaningless.
5. id vs class?
id unique/one element; class reusable/many elements; id has higher CSS specificity.
6. strong vs b?
strong = semantic importance; b = visual only.
7. em vs i?
em = stress/meaning change; i = alternate voice, no emphasis.
8. section vs article?
article = standalone content; section = themed grouping, not standalone.
9. GET vs POST?
GET = params in URL, visible, cacheable, idempotent; POST = body data, creates/changes data.
10. What is the DOM?
Live in-memory tree of parsed HTML that JS reads/modifies.
11. Accessibility?
Designing so people with disabilities can perceive/navigate/interact with a page.
12. ARIA?
Attributes adding accessibility info to custom widgets when no native tag fits.
13. iframe?
Embeds another HTML document inside the current page.
14. DOCTYPE purpose?
Declares HTML5, forces standards-mode rendering.
15. Why viewport meta tag?
Without it mobile browsers render desktop-width and zoom out; the tag matches width to device.
16. Block vs inline?
Block = new line, full width (div, p, h1); inline = flows within line (span, a, strong).
17. Void elements?
No closing tag/content: img, br, input, hr, meta, link.
18. HTML entity?
Reserved code (&lt;) to display characters that are otherwise HTML syntax.
19. Client-side validation?
Browser-level form checks (required, pattern) before sending to server.
20. Why isn't it enough for security?
Can be bypassed/disabled; server must independently validate all input.
21. Purpose of alt?
Screen-reader description, fallback on load failure, image-search indexing.
22. Why avoid tables for layout?
Breaks accessibility/responsiveness; tables are for tabular data only.
23. button vs anchor?
button = triggers action, no navigation; a[href] = navigates to a resource.
24. async vs defer?
async = runs as soon as downloaded, unordered; defer = runs in order after parsing.
25. Browser load sequence?
DNS → HTTP request → HTML response → parsed to DOM → CSSOM built → render tree → layout → paint → linked JS executes.
